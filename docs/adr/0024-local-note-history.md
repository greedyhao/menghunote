# ADR 0024 — 笔记编辑历史：本地优先

> 状态：**已决，待实现**（2026-11-19，用户确认：先做本地历史，跨设备一致历史后置）。
> 关联：ADR 0001（SQLite 真源）、ADR 0002 §8（会话内 undo）、ADR 0006（同步/加密）、
> `docs/briefs/0006-history-and-trash.md`（完整范围与待决问题）。

## 1. 背景

正文是 Loro CRDT，本地 `loro_updates` 保存完整 op log；当前只有会话内 undo/redo，
没有跨重启的「查看/恢复历史版本」。同步会把远端 op 合并进本地库，但 relay 只保存
密文事件流且 7 天 GC，不能作为历史查看的数据源。

用户选择：**先做本机历史，跨设备一致的版本元数据后置**。

## 2. 决策

### 2.1 数据来源与范围

- 历史来源是**本地 SQLite**：`loro_updates` + snapshot；不查询 relay 旧日志。
- 版本索引只记录本机看到的历史。同步导入的远端修改会在本机形成版本；
  新设备 bootstrap 后可能没有旧版本元数据，这是 v1 的已知边界。
- v1 **不做**跨设备一致时间线；将来另加加密 history log（或专用 CRDT 文档），
  不复用 relay 明文查询。

### 2.2 版本粒度

- 不按每次按键记录；按「编辑会话」捕获：
  - 停止输入约 2 秒；
  - 切换笔记/关闭窗口；
  - 同步导入批次完成。
- 每个版本保存：`note_id`、创建时间、设备标识、来源（本地/同步导入/checkpoint）、
  标题、op 范围、压缩后的正文快照（首版允许整篇快照；后续可优化为增量）。
- 版本只追加，不改写 CRDT 历史。

### 2.3 查看与恢复

- 入口：笔记右键/侧栏菜单「历史记录…」，打开独立时间线覆盖层。
- 时间线显示时间、设备、变更摘要（diff 可选）；点击版本只读预览。
- 恢复默认 **恢复为新笔记**（append-only），不覆盖当前笔记；保留当前内容与历史。
- 不提供「改写过去 op」或管理员式历史编辑。

### 2.4 保留策略

- v1 默认保留最近 **200 个版本或 90 天**（先到者），不做自动物理裁剪 UI。
- 后续可加显式清理/保留策略；清理必须二次确认并说明「其他设备/历史 snapshot 可能仍含内容」。
- 历史是本机明文（与 ADR 0001 一致）；不进入同步正文，除非将来实现跨设备 history log。

### 2.5 与回收站的关系

- 本 ADR 只覆盖 H1 历史查看与恢复。
- 回收站（H2：列表/恢复/彻底删除）仍按 `docs/briefs/0006-history-and-trash.md` 单独排期；
  历史查看不应绕过 tombstone/删除语义。

## 3. 后果

- 新增本地历史表与快照存储；需要评估长文档/长历史的体积与加载性能。
- 版本捕获必须异步、可失败但不阻塞编辑；历史写失败只提示，不影响正文保存。
- 跨设备时间线、历史裁剪、回收站、审计归属均不在本切片。
- 实现顺序：storage 版本捕获/查询 → app 时间线覆盖层 → 恢复为新笔记 → headless/真机验收。

## 4. 待实现清单

1. `note_history` schema（版本元数据 + 压缩快照）与迁移。
2. 编辑会话收敛点、同步导入完成后的版本捕获。
3. 时间线查询/分页/只读预览。
4. 恢复为新笔记（一次结构提交，不覆盖当前）。
5. headless 测试：版本生成、时间线顺序、预览、恢复、失败不阻塞编辑。
6. 文档与 selector 约定。
