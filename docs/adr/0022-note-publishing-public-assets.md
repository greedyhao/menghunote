# ADR 0022 — 笔记发布与公开附件

> 状态：**已决**（2026-11-17，用户确认：公开附件单独存储；大体积附件默认不公开，
> 阈值 20 MiB；笔记发布用明文快照）。
> 关联：ADR 0006（sync v1，密文中继/快照）、ADR 0019（附件/资产模型）、
> ADR 0020（i18n 与插件边界）、ADR 0021（应用级主题）。
>
> 本 ADR 只决定发布模型与公开附件的边界，不包含实现切片、域名/计费/公开站点编辑器。
> 发布是**显式动作**，不是同步的副作用。

## 1. 背景

现有同步链路是**密文中继**：relay 只存密文/密文快照，不持有明文内容或密钥。
用户希望把部分笔记设为“已发布”，提供直链分享，并考虑子文档访问权限。

这会引入一个与同步完全不同的数据面：

- 浏览器需要直接访问公开页面和附件；
- relay/公开服务需要能返回明文（或至少浏览器可解密的内容）；
- 子文档、附件、撤销、权限都需要服务端参与。

不能把“发布”实现成同步数据上的一个布尔字段，否则会破坏 E2E 边界与 ACL 语义。

## 2. 决策

### 2.1 发布内容用独立的明文快照

- 发布时由客户端生成**不可变明文快照**：渲染后的 HTML/Markdown + 公开资源副本；
- 快照上传到**独立的公开内容存储/服务**，与私有同步库分离；
- 发布记录不写回笔记正文，不进入 CRDT，不改变私有同步 schema；
- 私有同步链路继续使用密文，不因为发布而解密/降级。

### 2.2 私有附件与公开附件分开存储

- 私有附件：继续留在私有 `assets`/同步链路中，按现有加密/ACL 处理；
- 公开附件：只在发布时按引用复制到 `public_assets`，**明文**存储；
- **不把整个 vault 的附件改成不加密**；这是明确拒绝的方案；
- 公开副本不是私有附件的替代品，私有原件始终保留；
- 只有已发布文档实际引用的附件才复制；未发布文档的附件不进入公开存储。

### 2.3 大体积附件默认不公开

- 单附件公开阈值：**20 MiB**（`20 * 1024 * 1024` 字节；`<=` 允许，`>` 拒绝公开）；
- 超过阈值的附件默认**不复制**到公开存储；
- 公开页面中对应位置显示“附件未公开（超过 20 MiB）”占位，不暴露私有 URL/路径；
- 发布本身可以成功，但必须给出明确警告和缺失附件列表；
- 首版不提供“强制公开超大附件”的 UI；后续如需，必须单独确认、单独配额/审计；
- 阈值集中定义（服务端与客户端同一常量），后续可配置，但首版不可由笔记内容覆盖。

### 2.4 公开附件按内容寻址、引用计数、可撤销

公开存储建议模型：

```text
publications(id, note_id, slug, revision, access, expires_at, created_at, updated_at)
public_assets(hash, byte_len, media_type, bytes, created_at)
publication_assets(publication_id, asset_hash)
```

- `public_assets.hash` = 内容 SHA-256，同字节去重；
- `publication_assets` 建立引用；取消发布时减引用，无引用再 GC；
- 同一个附件可被多个发布共享公开副本，但访问仍按 publication 的 ACL/链接校验；
- 私有 `assets` 表不改；公开表不进入同步 schema；
- 公开对象 URL 使用不可猜 hash/随机 slug，不做目录列表。

### 2.5 子文档权限

- 发布单位：单篇笔记 + **显式选择**的子文档；父文档发布不自动公开整棵子树；
- 未发布子文档默认拒绝，返回 404/无权限，不泄露标题；
- 子文档直链可独立访问（若已发布），面包屑只显示已公开祖先；
- 父文档中指向未发布子文档的链接显示“私有内容”占位，不自动公开；
- 反向链接、搜索、目录列表不暴露未发布文档；
- 资产只按已发布文档引用公开；未发布子文档引用的附件不公开。

### 2.6 安全与访问控制

- 首次发布必须明确提示“发布后公开服务可见明文”；用户确认后才上传；
- 公开页面：`noindex`、CSP、sanitize HTML、禁止脚本/事件属性/原始 HTML；
- 附件：
  - 只允许白名单类型（图片/PDF/纯文本等）；
  - 非图片类型使用 `Content-Disposition: attachment`，避免浏览器内联执行；
  - SVG/HTML 默认按下载处理，不执行；
  - 去掉 EXIF/文件名等敏感元数据；
  - 公开 URL 不可猜，但不把“不可猜”当唯一权限；
- 可选密码/过期时间；撤销后旧链接 404/410，CDN 缓存短 TTL；
- 限流、租户隔离、审计（谁在何时发布/撤销），日志不记录明文内容；
- `javascript:`/`data:` 等危险 URL 不进入公开页面。

### 2.7 与同步的关系

- 发布/撤销是**显式用户动作**，不影响同步调度与本地编辑；
- 公开快照是发布时的版本，不自动跟随私有同步；后续可做“重新发布”；
- 公开服务不读取私有 relay 的密文数据面，也不持有私有密钥；
- 多设备：发布记录由公开服务保存，客户端按 publication id 管理；不写进正文。

## 3. 首版 MVP

1. 单篇笔记发布/撤销，生成不可变 HTML 快照；
2. 公开附件按引用复制到独立 `public_assets`，20 MiB 上限；
3. 不可猜直链 + `noindex`；可选密码/过期；
4. 子文档默认私有，显式发布子文档后才可直链访问；
5. 取消发布删除公开快照/引用，私有原件不受影响；
6. 发布前确认“公开明文”，发布后显示缺失附件/超限警告；
7. 公开服务与 relay 数据面分离，不改同步 schema/协议。

## 4. 非目标（首版）

- 不把私有附件全局改为不加密；
- 不把公开内容塞进现有密文同步表；
- 不做浏览器端加密发布/链接 fragment 解密；
- 不做公开站点编辑器、自定义域名、评论、访问统计；
- 不做超大附件强制公开；
- 不做每篇笔记独立主题/每篇笔记独立权限模型（主题见 ADR 0021）。

## 5. 后果与风险

- **存储成本**：公开附件是额外副本；用只公开引用、内容寻址、引用计数、20 MiB 上限和配额控制；
- **撤销不彻底**：浏览器/CDN 缓存可能保留旧副本；需要短 TTL 与明确提示；
- **公开即泄露**：用户可能误发布敏感内容；首次确认、预览、缺失附件警告、撤销入口必须清晰；
- **子文档 ACL 复杂**：默认私有、显式选择、父不自动包含子，避免“发布父文档泄露整棵树”；
- **附件类型安全**：SVG/HTML/PDF 可能带脚本/外链；必须白名单 + 下载语义 + sanitize；
- **服务端明文**：与现有 E2E 边界不同，必须独立服务/独立存储/独立审计，不能悄悄复用 relay 密文接口。

## 6. 待决问题

1. 公开服务与 relay 是同进程不同路由，还是独立部署/独立数据库（建议后者）。
2. 发布快照格式：HTML 为主，是否同时保留 Markdown 源/JSON API。
3. 20 MiB 阈值后续是否可配置、是否允许单次显式覆盖（首版不允许）。
4. 公开附件的总配额、单租户上限、过期清理策略。
5. 子文档批量发布的选择 UI 与默认勾选策略。
6. 撤销后 404 还是 410，CDN 缓存 TTL 与刷新流程。
